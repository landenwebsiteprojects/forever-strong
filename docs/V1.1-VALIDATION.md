# ForeverStrong v1.1 validation

The actual Integrity Box v45 ZIP was downloaded and matched its published SHA-256: `f217bcaf24d4659bd023f7d44749a5de1251d8b4f6b6da96a8b307b496669c5f`. Its original files are preserved under `upstream/integrity-box-v45-archive`. Packaged v45 differs from the GitHub tag's source; comparisons use the official release archive. The existing `archive/Megatron` endpoint is still published. No claim is made that the screenshot's root-shell DNS failure was a missing upstream asset.

The installed native libraries for ARM64, ARMv7 and x86_64 are v45 payloads. Only the existing fixed-width module path is relocated; original/relocated hashes and occurrences are recorded in `NATIVE-RELOCATION.json`. There is no installed v44 legacy library. Retrieved PlayIntegrityFork source is pinned at `42ebfb38af8ff29d75dce1a378cbd682ffe5501d`; dependency source trees already present in the project are retained. This is release-payload integration, not a claim that the supplied native binaries were rebuilt bit-for-bit.

Host checks cover installer extraction and upgrade preservation on supported managers, root tool selection, secure configuration operations, engine ownership and repair routing, native payload provenance, and the actual download fallback chain. Download fixtures exercise a failed first tool, subsequent wget/BusyBox success, per-request DNS resolution with redirect hosts, exhausted/empty responses, and active-file preservation. The real keybox decoding/staging pipeline is exercised with the real Java validator against invalid and valid data. The real v45 action sequence is checked for failure propagation at the download, fingerprint, target and patch stages.

The WebUI suite uses Chromium and a mocked root bridge. It loads all 20 controls, runs the repair confirmation/routing flow, checks persistent appearance and shared navigation, and checks narrow-screen layouts. These are browser/host results, not Android WebView or native-injection tests. Individual results are in the corresponding `*-TEST-RESULTS.json` files.

The update feed is tested against the exact module ZIP: stable module ID, version, integer versionCode, pinned ZIP and notes URLs, and the standard manager JSON schema. GitHub Actions independently compiles the validator and repeats the host/browser checks before publishing. Assets are uploaded to a draft, and the release becomes latest only after the complete package exists. Subsequent releases require an increased versionCode and cannot overwrite an existing published tag.

No rooted Android phone is connected to the build environment. Boot stability, active injection, manager-specific update presentation, and repair over the user's actual network still require on-device confirmation. Process presence is not proof of interception or a Play Integrity verdict. Existing app-key persistence, target scopes and patch preservation rules remain in force.
